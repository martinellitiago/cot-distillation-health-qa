# Data

The complete study population: **4,260 items** from the **2024 and 2025**
Brazilian health professions examinations, plus the teacher rationales distilled
from them.

Our internal item bank spans 2011–2025 (5,831 items), but every experiment in the
paper was run on the 2024/2025 items only. This release is therefore the study
population itself, not a subsample of it.

## Files

### `questions_2024_2025.jsonl`

One JSON object per line.

| field | type | meaning |
|---|---|---|
| `id` | string | stable item identifier; the join key across all files |
| `source` | string | examining body (see below) |
| `exam_year` | int | 2024 or 2025 |
| `stem` | string | the question stem, Portuguese, verbatim |
| `options` | object | `{"A": "...", ..., "E": "..."}` |
| `gold_answer` | string | the official answer key, `A`–`E` |
| `has_image` | bool | the item refers to a figure (see *Images* below) |

| source | items |
|---|---|
| Enare Residência Médica | 2,691 |
| Enare Multiprofissional | 1,164 |
| INEP | 287 |
| FUVEST | 118 |
| **total** | **4,260** |

By exam year: 2024 — 4,162; 2025 — 98.

### `teacher_rationales.jsonl`

One JSON object per line, joined to the questions on `id`. These are **model
outputs**, generated by us with **Qwen3-32B** in non-thinking mode; they are not
examination material.

| field | type | meaning |
|---|---|---|
| `id` | string | join key |
| `rationale` | string | the teacher's reasoning, Portuguese |
| `teacher_answer` | string | the teacher's answer as parsed by the **original** parser |
| `teacher_answer_audit` | string | the same answer re-extracted by the **audit** parser |
| `parsers_disagree` | bool | the two parsers returned different letters |
| `teacher_correct` | bool | `teacher_answer == gold_answer` — **the study label** |
| `teacher_correct_audit` | bool | `teacher_answer_audit == gold_answer` |
| `n_tokens` | int | tokens generated by the teacher |

**Which label to use.** `teacher_correct` is the label the paper's A/B/C/D
partition was built from, so it is the one that reproduces the published results.
`teacher_correct_audit` is published for transparency, not as a replacement:
substituting it would silently redefine the strata and detach this data from the
paper's numbers.

**The two parsers disagree on 77 items (1.81%).** Against the answer key, the
original parser is right and the audit parser wrong on 44 of them; the reverse
holds on 18; both are wrong on 15. Net teacher accuracy is therefore **0.748**
under the original parser and **0.742** under the audit parser. Extracting a
final answer from free-form text with regular expressions is brittle in both
directions, which is precisely why both columns are shipped rather than one.

## Images

45 of the 4,260 items refer to a figure. The images are **not** redistributed, and
the items were processed as text throughout the study — the model saw the stem
and options only. They are flagged with `has_image` so they can be excluded. The
ENEM forgetting probe (`code/probes/`) excludes image items explicitly and
operates on a separate 395-item image-free sample.

## Provenance

`questions_2024_2025.jsonl` and `teacher_rationales.jsonl` are produced by
`code/data_prep/build_dataset.py` from two internal archives
(the full item bank and the teacher generation archive). That script is the
auditable record of how this release was cut.

Rationales are matched to items by a **whitespace-normalised, lowercased stem**,
because the teacher archive does not carry the item id. All 4,260 teacher rows
matched an item. A small number of items share a normalised stem, which makes the
mapping ambiguous for those few; this shifts the teacher accuracy computed from
these files by about 0.1 pp relative to computing it directly on the internal
archive (0.748 here against 0.749 there). The subsequent analysis is unaffected,
because the study partition was built on the internal archive.

## What is not here

- **The A/B/C/D subset labels and the per-seed splits.** These depend on the
  *untrained* student's per-item correctness, which lives in the split files
  produced on the training machine. Regenerate them with
  `code/data_prep/regenerate_splits.py` after running the untrained
  baseline probe, or request the split files from the authors.
- **Images** (see above).
- **Trained LoRA adapters.** Available on request; they are large and cheap to
  reproduce from this data.
